# Manager action coverage

This is the implementation and verification ledger for the AI launcher. A route that merely opens a settings page does not complete a requested edit. Supplied names, values, selections, and operation directions must survive into the existing review control. Every write still requires the existing save, review, browser, or wallet confirmation.

Current implementation: the AI launcher has bounded handoffs for the existing Manager flows below, including 29 account, sharing, notification-channel, migration-permission, NFT, primary-profile navigation, current-owner review and profile-address-copy actions. The handoffs have non-TSX parser/preparation/routing tests; verified browser reviews and remaining gaps are marked separately below. Profile editing has its own inventory and is intentionally not expanded here. Missing exact inputs open targeted controls, and explicit values are retained for review.

## No existing reusable Manager flow found

- [ ] Transfer/sell/burn/delete a name: not an existing Manager UI action in this checkout. Notification kinds and migration-internal transfers are not a general transfer flow.
- [ ] Create/delete subnames, deploy a child registry, arbitrary role/manager/permission editing: no existing page/dialog found. Migration carries eligible parent/subname groups but does not expose these standalone edits.
- [ ] Arbitrary resolver replacement/permissions: profile save/setup uses `changeResolver`, `setupControlledResolver`, and `setResolverAccess` internally; these are not a general user-facing resolver editor.
- [ ] Clear/remove primary name: the existing chooser selects a name; no dedicated clearing control found.
- [ ] DNS import: profile route recognizes DNSSEC support but no import flow found.
- [ ] Schedule future transactions, custom notification schedules, disable in-app notifications, search notification text, arbitrary NFT export formats: not implemented controls.
